# Lab: file system

在本实验中，你将向 xv6 文件系统添加大文件（large files）和符号链接（symbolic links）。

## Large files (moderate)

在此任务中，你将增加 xv6 文件所能达到的最大大小。目前，xv6 文件被限制为 268 个块（blocks），即 268*BSIZE 字节（在 xv6 中，BSIZE 是 1024）。该限制源于 xv6 的 inode 包含 12 个“直接”（direct）块号和 1 个“一级间接”（singly-indirect）块号，该间接块指向一个最多包含 256 个块号的块，因此总共有 12+256=268 个块。

`bigfile` 命令会创建它所能创建的最长文件，并报告其大小：
```
$ bigfile
..
wrote 268 blocks
bigfile: file is too small
$
```
测试失败是因为 `bigfile` 期望能够创建一个拥有 65803 个块的文件，但未修改的 xv6 将文件限制为 268 个块。

你将修改 xv6 文件系统代码，以支持在每个 inode 中拥有一个“二级间接”（doubly-indirect）块，该块包含 256 个一级间接块的地址，其中每个一级间接块可以包含最多 256 个数据块的地址。其结果是文件将能够包含最多 65803 个块，即 256*256+256+11 个块（这里是 11 而不是 12，因为我们将牺牲其中一个直接块号来用于二级间接块）。

### Preliminaries

`mkfs` 程序创建 xv6 文件系统磁盘映像并确定文件系统总共有多少个块；该大小由 `kernel/param.h` 中的 `FSSIZE` 控制。你会在本实验的仓库中看到 `FSSIZE` 被设置为 200,000 个块。你应该在 make 输出中看到来自 `mkfs/mkfs` 的以下输出：
```
nmeta 71 (boot, super, log blocks 31, inode blocks 13, bitmap blocks 25) blocks 199929 total 200000
```
该行描述了 `mkfs/mkfs` 构建的文件系统：它有 71 个元数据块（用于描述文件系统的块）和 199,929 个数据块，总计 200,000 个块。

注意，`make qemu` 会构建一个新的 `fs.img`，并将旧的保存为 `fs.img.bk`。如果你想用现有的 `fs.img` 运行 xv6，而不是构建一个新的，请运行 `make qemu-fs`。

### What to Look At

磁盘上 inode 的格式由 `fs.h` 中的 `struct dinode` 定义。你尤其需要关注 `NDIRECT`、`NINDIRECT`、`MAXFILE` 以及 `struct dinode` 中的 `addrs[]` 元素。请查看 xv6 课本中的图 10.3 以获得标准 xv6 inode 的图解。

在磁盘上查找文件数据的代码在 `fs.c` 中的 `bmap()`。看一下它，并确保你理解它在做什么。无论是读取还是写入文件，都会调用 `bmap()`。写入文件时，`bmap()` 会根据需要分配新块来保存文件内容，并在需要时分配间接块来保存块地址。

`bmap()` 处理两种块号。`bn` 参数是“逻辑块号”——即文件内部的块号，相对于文件的开头。`ip->addrs[]` 中的块号以及传递给 `bread()` 的参数都是磁盘块号。你可以将 `bmap()` 视为将文件的逻辑块号映射到磁盘块号。

### Your Job

> [!IMPORTANT]
> 修改 `bmap()`，使其在直接块和一级间接块之外，实现一个二级间接块。你将必须只保留 11 个直接块，而不是 12 个，以便为你的新二级间接块腾出空间；你不允许修改磁盘上 inode 的大小。`ip->addrs[]` 的前 11 个元素应为直接块；第 12 个应为一级间接块（就像当前的一样）；第 13 个应是你的新二级间接块。当 `bigfile` 成功写入 65803 个块且 `usertests -q` 运行成功时，你就完成了这个练习：

```
$ bigfile
.................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................
wrote 65803 blocks
done; ok
$ usertests -q
...
ALL TESTS PASSED
$ 
```

运行 `bigfile` 至少需要分半钟。

提示：

* 确保你理解 `bmap()`。画一张图来展示 `ip->addrs[]`、一级间接块、二级间接块及其指向的一级间接块以及数据块之间的关系。确保你理解为什么增加二级间接块会将最大文件大小增加 256*256 个块（实际上是 -1，因为你必须将直接块的数量减少一个）。
* 思考如何使用逻辑块号对二级间接块以及它所指向的一级间接块进行索引。
* 如果你修改了 `NDIRECT` 的定义，你可能必须在 `file.h` 的 `struct inode` 中更改 `addrs[]` 的声明。确保 `struct inode` 和 `struct dinode` 在它们的 `addrs[]` 数组中具有相同数量的元素。
* 如果你更改了 `NDIRECT` 的定义，请确保创建一个新的 `fs.img`，因为 `mkfs` 使用 `NDIRECT` 来构建文件系统。
* 如果你的文件系统进入了坏状态（可能是因为崩溃了），请删除 `fs.img`（从 Unix 终端执行此操作，而不是在 xv6 中）。`make` 将为你构建一个新的干净文件系统映像。
* 别忘了对每个你调用过 `bread()` 的块调用 `brelse()`。
* 你应该像原本的 `bmap()` 那样，仅在需要时才分配一级和二级间接块。
* 确保 `itrunc` 释放文件的所有块，包括二级间接块。
* `usertests` 的运行时间比以前的实验长，因为在此实验中 `FSSIZE` 更大，且大文件也更大。

## Symbolic links (moderate)

在此练习中，你将向 xv6 添加符号链接（或软链接）。符号链接通过路径名引用链接的文件或目录；当打开符号链接时，内核会查找被链接的名称。符号链接类似于硬链接，但硬链接被限制为只能指向同一磁盘上的文件，不能引用目录，并且绑定到特定的目标 inode，而符号链接是指向目标名称当前所对应的任何内容（如果存在的话）。实现该系统调用是理解路径名查找工作原理的极佳练习。

在本实验中，你不需要处理指向目录的符号链接；唯一需要知道如何跟踪符号链接的系统调用是 `open()`。

### Your job

> [!IMPORTANT]
> 你将实现 `symlink(char *target, char *path)` 系统调用，它在 path 处创建一个新的符号链接，该链接引用 target 命名的文件。有关更多信息，请参阅 symlink 的手册页。为了测试，将 `symlinktest` 添加到 Makefile 并运行它。当测试产生以下输出（包括 usertests 成功）时，你的解决方案就完成了。

```
$ symlinktest
Start: test symlinks
test symlinks: ok
Start: test concurrent symlinks
test concurrent symlinks: ok
$ usertests -q
...
ALL TESTS PASSED
$ 
```

提示：

* 首先，为 `symlink` 创建一个新的系统调用号，将其条目添加到 `user/usys.pl`、`user/user.h`，并在 `kernel/sysfile.c` 中实现一个空的 `sys_symlink`。
* 在 `kernel/stat.h` 中添加一个新文件类型（`T_SYMLINK`）以表示符号链接。
* 在 `kernel/fcntl.h` 中添加一个新标志（`O_NOFOLLOW`），可用于 `open` 系统调用。注意，传递给 `open` 的标志是使用按位或操作符组合的，因此你的新标志不应与任何现有标志重叠。这会让你在将 `user/symlinktest.c` 添加到 Makefile 后能够编译它。
* 实现 `symlink(target, path)` 系统调用，以便在 `path` 处创建一个指向 `target` 的新符号链接。注意，系统调用成功并不要求 `target` 必须存在。你将需要选择某个地方来存储符号链接的目标路径，例如存储在 inode 的数据块中。`symlink` 应返回一个表示成功（0）或失败（-1）的整数，类似于 `link` 和 `unlink`。
* 修改 `open` 系统调用以处理路径引用符号链接的情况。如果文件不存在，`open` 必须失败。当进程在 `open` 的标志中指定 `O_NOFOLLOW` 时，`open` 应该打开符号链接本身（而不跟踪符号链接）。
* 如果链接的文件也是一个符号链接，你必须递归跟踪它，直到到达一个非链接文件。如果链接形成环路，你必须返回一个错误码。如果链接的深度达到某个阈值（例如 10），你可以通过返回错误码来近似实现这一点。
* 其他系统调用（例如 `link` 和 `unlink`）不得跟踪符号链接；这些系统调用操作的是符号链接本身。
